# Technical Design Document — Jigsaw Puzzle Collector

Status: foundation plus Bulk Photo Import MVP. See `docs/BULK-PHOTO-IMPORT.md` for the authenticated routes, private storage, additive migrations, provider boundary and test isolation.

## Architecture

Modular monolith: static React/TypeScript/Vite frontend; versioned PHP 8.3 REST API on Apache; MySQL 8 database. Target deployment: shared Apache/PHP hosting, without a persistent Node server. Frontend compiled to static assets. Local Docker Compose provides `frontend`, `api` and `db` services.

## Data model

The private collection frontend derives summary totals, manufacturer groups, known piece counts, search, piece filters and sorting from the existing owner-authorized `/api/collection` response; no demo records or fabricated classifications are merged into signed-in data. Gallery/list presentation uses the same image URLs and selected studio assets. Filters and view state remain local to the mounted collection so opening details and returning preserves them. The existing newest-1000-copies response limit still applies; server pagination/global aggregate totals are separate future work for collections beyond that window.

`puzzles` (identity), `editions` (release), `owned_copies` (physical copy), `users` and future `edition_images`, `owned_copy_images`, `audit_events`, `catalogue_contributions`. Initial SQL migration creates four core tables. Foreign keys enforce identity → edition → copy relationships. Monetary fields store decimal values and currency codes; timestamps UTC.

## API

`GET/PATCH /api/collection-copies/{id}` reads/edits one owner-authorized copy regardless of gallery pagination. PATCH requires session, CSRF, integer `revision` and an allowlisted partial `fields` object. Migration 006 adds nullable `owned_copies.field_overrides`, `edit_revision` defaulting to 1 and `owned_copy_edits`. Title/manufacturer/piece count/SKU/year use per-copy JSON overrides; an absent key inherits the edition, while explicit JSON null means unknown. Physical attributes use their existing copy columns. The shared serializer and Home SQL aggregate resolver both apply these values. Never update shared puzzles/editions or import/image/provenance records. A transaction locks the owned row, checks its revision, validates fields, writes changed values/revision and before/after history atomically. No-ops do not increment revisions or create history; missing/foreign copies return 404, invalid fields 422 with field messages, stale revisions 409. Notes are bounded plain text. Shared details reload the latest revision on Edit, preserve drafts on failure, and require explicit discard before loading conflicting server values. Save updates local gallery/recent-copy data and refreshes Home aggregates; late refresh responses are discarded after auth/navigation changes. A cancellable navigation event protects dirty/saving editors; `beforeunload` covers leaving the page. Existing Make unit targets include editing tests; ownership/CSRF/source-integrity API and mobile browser cases remain in the full CI gate.

`GET /api/home` is session/owner protected and read-only. `HomeSummary` computes counts directly over all owned copies (case/whitespace-normalized known manufacturers; null piece counts excluded), plus the newest three nondeleted batches with queued/processing/image-review/identity-review/approved/failed items. Completed/rejected-only and empty batches are excluded. SQL aggregates avoid fetching every item or deriving totals from the Collection API's 1,000-copy window. The response adds six recent copies ordered by creation time/id using the existing collection serializer and private image routes; no image processing or schema migration is needed. `PrivateCopyDetails` is shared by Home and Collection. Add accepts an explicit initial batch ID, ahead of local resume state, and verifies ownership through the existing API. Component requests discard late results after authentication changes/unmount. Home unit coverage is part of existing frontend/PHP Make targets; API ownership/large-collection and Playwright resume cases remain in the unchanged full CI gate.

The frontend initializes authentication with `/api/session`. Header Log in opens a dedicated account screen using existing login/register endpoints; only a successful authenticated response enables Add. Saved Add navigation cannot bypass the signed-out gate. Add rechecks the session but never renders login fields. Login requests disable navigation/repeat submissions until completion; failed requests retain signed-out state. Sign out clears private views and returns to public illustrative browsing. Portrait WebKit touch layout adds 40 px to the safe-area header offset, shared with detail positioning, with an opaque header surface rather than a claimed browser-blur override.

`GET /api/health` reports API availability. The import MVP implements same-origin `/api/session`, `/api/auth/register|login|logout`, `/api/import-batches`, `/api/import-items/{id}` and `/api/collection`. Session cookies and CSRF tokens protect writes; owner checks protect every private record and image. SQL uses prepared statements. Future general catalogue/CRUD versioning remains planned; no cross-origin API access is enabled. HTTPS and secure cookies are mandatory outside local HTTP development.

## Development

Windows 11 + WSL2 or PowerShell, Docker Desktop, GNU Make as the standard entry point. `.env.example` contains development-only defaults; real secrets are never committed. `make migrate` applies ordered SQL/PHP migrations under a database advisory lock and records successful application. Validate backups and restore procedures before any staging or production use; production deployment remains disabled.

## Quality gates

During the current development phase, run `make test-unit-dev` before `make dev`. This runs frontend, PHP and image-processing unit tests only, without browser/load/integration gates. Keep `make ci` and all full-gate requirements intact for production promotion; do not treat unit-only development verification as production readiness. No production deployment is authorized.

`make ci` invokes lint/typecheck, Vitest, PHPUnit, Playwright, API smoke, and k6 baseline load. GitHub Actions runs a baseline workflow. Before first production deployment, validate test isolation, migrations, integration coverage, browser execution, load thresholds, and post-deploy smoke in real staging. Deployment is disabled in this starter. Long-running stress/spike/soak tests run on a schedule or significant releases.

## Images

Batch deletion uses additive migration 005 (`import_batches.deleted_at` and an owner-scoped image-cleanup queue). `DELETE /api/import-batches/{id}` locks/authorizes the batch, deletes only unimported/unreferenced draft items/events, queues unreferenced photos and hides the batch atomically. Imported source items, photos and provenance remain linked through a minimal retained batch record. Repeated deletion is idempotent. All batch mutation/resume paths reject deleted batches; private collection image lookup remains independent of batch visibility. File cleanup runs after commit, validates server-generated keys, removes only known variants, and releases image storage/quota only after successful cleanup. Failure leaves a durable owner-only retry job; `POST /api/import-batches/cleanup` retries up to 100 jobs. No existing batch is deleted automatically by migration.

After rectification, `processing/orientation.py` evaluates four clockwise quarter-turns with local Tesseract English OCR (`--psm 11`, TSV). Full-front and overlapping horizontal-band scans isolate lettering at any height without fixed logo positions; normalized tokens are deduplicated. Confidence, horizontal word shape, fuzzy manufacturer matching (Springbok, Ravensburger, Aquarius, Buffalo, Ceaco, White Mountain), common packaging labels and subordinate numeric counts contribute evidence. TSV is parsed without CSV quote escaping so literal OCR quotes cannot consume subsequent rows. Each subprocess has a 1.5-second bound and one OpenMP thread. Close rankings (margin below 0.20), insufficient support or incomplete scans flag orientation review. Low mean text confidence is stored separately and does not force review when a clear orientation wins. OCR normalization never alters artwork; scores are heuristics, not probabilities.

`preprocessing.orientation` stores the applied angle, source (`ocr`, `manual`, or portable `unavailable`), ambiguity/reason and OCR candidates. The existing JSON column is sufficient; no destructive or data-reset migration is needed. `POST .../preprocessing/prepare` accepts an optional absolute `rotation` of 0/90/180/270. PHP validates the angle and revision, takes an existing manual angle when no replacement is supplied, and requires the remote worker to honor manual overrides. A saved zero is preserved. Corner coordinates remain in EXIF-oriented source space; rotation occurs after homography, so reprocessing cannot accidentally accumulate quarter-turns. The catalogue and corrected thumbnail are encoded from the same rotated pixels; studio rendering consumes that exact catalogue image. The portable GD processor applies the same manual rotations but explicitly flags missing OCR. Existing imported records remain closed to in-place reprocessing.

Preprocessing uses a separate optional Python/OpenCV service (`processing/`) with no host port or database access. PHP sends one owner-authorized photo per bounded request over the internal Compose network using a processor key; only JPEG derivatives and validated metadata return. OpenCV proposes outer quadrilaterals using edges/contours and classical foreground segmentation, then uses `getPerspectiveTransform`/`warpPerspective`. There is no generative model, inpainting, artwork replacement, or external vision call.

`make dev` starts the optional processor profile. `make dev-php` uses a PHP/GD-only override; shared hosting with `IMAGE_PROCESSOR_URL` unset uses the same portable implementation without Python or a persistent worker. PHP provides four-point homography, bilinear resampling, conservative colour/exposure/contrast/sharpening, and a deliberately low-confidence boundary heuristic. It caps its catalogue result at 1,200 pixels to bound shared-hosting CPU. Both modes retain manual correction and explicit image choice.

Migration 004 only adds nullable processing metadata; it does not reset existing reviews, approvals or imported records. New uploads enter `image_review` before extraction. Processing metadata records oriented source dimensions, normalized clockwise corners, confidence/warnings, engine/version, settings, revision, original SHA-256, private derivative keys and byte accounting. Explicit reprocessing invalidates that item's image/identity approval while preserving saved human edits. Revision checks reject stale edits and decisions. Imported source records are immutable; owned-copy corrections are stored separately. Derivatives remain private and count toward quota; original bytes are never rewritten. File failures roll back metadata and clean newly written derivatives.

Each processing request handles one photo; identification reads the explicitly selected image. The deterministic fixture provider uses the original fingerprint as lookup context so cropping does not masquerade as real OCR or lose fixture identity. Unknown fields remain null. A processing outage is actionable: retry or explicitly keep the original. There is no silent remote-to-local fallback.

`make test-preprocess` runs OpenCV tests against all ten photographs plus annotated outer corners, rotation, poor lighting, skew, enhancement bounds, and invalid inputs. PHP tests exercise the portable engine and API ownership/revision/failure cases. Frontend/Playwright tests cover comparison, corner inputs and keyboard handles, low-confidence warnings, image choice, theme and reduced motion. `make ci` includes every existing gate plus preprocessing tests; `make inspect-preprocess` creates a local ignored contact sheet for visual review.

Reference mockups live in `docs/design/mockups`. Uploaded originals are stored privately outside the document root with their bytes intact. Owner-authorized display thumbnails apply EXIF orientation, resize to 800 pixels, and remove source EXIF metadata. MIME/size/dimension/decoding checks, private image authorization, storage quota and upload limits are implemented; public photo sharing remains planned.

## AI-agent workflow

### Individual copy deletion

`DELETE /api/collection-copies/{id}` requires owner session, CSRF and a positive integer `revision`. `CopyDeletionService` locks the owner and copy, rejects stale revisions with 409, and atomically removes copy/edit history while recording a minimal owner-scoped deletion marker. Repeated owner requests return success; foreign or unknown IDs return 404. Migration 007 adds markers and an image cleanup-key registry. Shared identities and other copies remain intact. Active import sources retain history; hidden-batch sources are removed only after their final copy reference disappears. Import commit excludes marked sources.

`PhotoCleanupQueue` records original/derived asset keys before source metadata disappears, retains them while any image references remain, and queues only unreferenced photos. Existing cleanup rechecks references, removes files, then releases image quota; failures preserve a retryable job. No Python dependency is added. Home refresh sequencing rejects older responses after deletion; Collection removes only the selected copy and restores focus. See `docs/COPY-DELETION.md` for verification scope.

### Studio presentation

`processing/studio.py` projects a corrected front onto a width/height/depth cuboid. `studio_config.json` supplies millimetre depth presets, estimated front scale and Front/Three-quarter cameras (12° yaw, 8° downward view by default). The standing-box reference determines the visible left side/top and ground-plane shadow concentrated at the base, rather than an outline shadow around the whole artwork. Neutral facets, conservative edge tint and upper highlights add no side artwork. Transparent lossless WebP assets are generated at import/settings changes (1200 pixels; thumbnails 400). Render metadata records dimensions, estimated/user-supplied provenance, camera and transform. Verified product dimensions are never inferred or written. Supplied front proportions must match the corrected front within 2%; exact artwork aspect is preserved using supplied width as the scale and retaining the entered height in metadata.

`make inspect-studio` emits Original/Corrected/Previous/Improved and light/dark sheets plus three aspect-ratio close-ups. `processing/references/studio_v2.py` freezes the previous renderer solely for visual comparison, using the same corrected front. Proof signatures include source hash, processing version, renderer config and manual angle. Canonical numbered fixtures exclude additional user-created Copy files. Generated proofs are private/ignored; originals are checksum-verified. Streaming tests cover 600 renderer items; this is not a full-resolution HTTP throughput claim.

The existing private worker adds authenticated `/studio`; PHP stores status/settings/dimensions/paths in existing preprocessing JSON with separate private studio keys and quota-accounted bytes. `POST .../preprocessing/studio` updates presentation independently of corrected pixels and identity approval, validates revisions, and reuses unchanged geometry for background/enable changes. Changed corrected pixels regenerate dependent studio assets. File/DB failures retain previous images and clean new files; old studio files are removed only after commit. Import review can opt out; the gallery uses studio only when available, enabled and the corrected image was accepted. Details offer studio/corrected/untouched-original routes, all owner-authorized. PHP-only mode reports studio unavailable and uses corrected images. No rendering runs on gallery GETs, no schema reset is added, and imported records are not automatically regenerated. Presentation settings are configured while the import draft is open.

Use separate branches/worktrees, smallest viable changes, and `make ci` before merge. Agents must not disable tests or alter production deployment gates to pass a change.
